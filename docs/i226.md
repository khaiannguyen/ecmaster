# Cài driver Intel I226-V (igc) trên Jetson Orin Nano

Ghi chú quy trình build driver `igc` cho card mạng M.2 E-Key 2.5G (chipset Intel I226-V, mã KTI226V-SRKTU) trên Jetson Orin Nano chạy JetPack R39 (kernel 6.8.12-1021-tegra, Ubuntu 24.04).

> **Cập nhật quan trọng:** máy đã chuyển sang chạy **kernel PREEMPT_RT** (`6.8.12-1021-rt-tegra`) cho dự án EtherCAT master. Vì đây là kernel khác (khác `uname -r`), toàn bộ quy trình dưới đây phải **build lại module riêng cho bản RT** — xem mục "Build lại cho kernel PREEMPT_RT" ở cuối file. Phần quy trình gốc bên dưới (cho kernel `-tegra` thường) vẫn giữ nguyên làm tham chiếu.

## Bối cảnh / Vấn đề

- Kernel Jetson (`nvidia-l4t-kernel`) **không build sẵn driver `igc`** (`CONFIG_IGC is not set`).
- Gói `linux-headers-*` của Jetson **bị cắt bớt rất nhiều file nguồn** cần thiết để build module ngoài — không chỉ thiếu driver, mà còn thiếu cả file build-tool phụ trợ của kiến trúc arm64.
- Do đó phải: (1) bổ sung các file bị thiếu để build hệ thống qua được, (2) lấy mã nguồn driver `igc` thật từ kernel.org, (3) build thành `igc.ko`, (4) cài persistent.

## Kiểm tra ban đầu

```bash
# Xác nhận PCI nhận diện card
lspci | grep -i ethernet
# → 0001:01:00.0 Ethernet controller: Intel Corporation Ethernet Controller I226-V (rev 04)

# Xác nhận driver igc chưa tồn tại
lsmod | grep igc
modinfo igc          # → modinfo: ERROR: Module igc not found.

# Thông tin kernel
uname -r              # 6.8.12-1021-tegra
cat /etc/nv_tegra_release
ls /usr/src/ | grep linux-headers
```

Xác định `/lib/modules/$(uname -r)/build` là **symlink** trỏ tới:
```
/usr/src/linux-headers-<ver>-ubuntu24.04_aarch64/3rdparty/canonical/linux-noble
```
→ Đây mới là thư mục "gốc" cần build, dùng path này thay vì path headers gốc.

## Bước 1: Bật CONFIG_IGC

```bash
cd /lib/modules/$(uname -r)/build
sudo scripts/config --file .config --module CONFIG_IGC   # hoặc dùng sed nếu không có scripts/config sẵn:
sudo sed -i 's/# CONFIG_IGC is not set/CONFIG_IGC=m/' .config
sudo make olddefconfig
```

> **Cách đơn giản hơn (xác nhận hoạt động tốt khi build lại cho kernel RT):** không cần sửa `.config` chút nào — truyền thẳng `CONFIG_IGC=m` trên dòng lệnh `make` ở Bước 4. `.config` vẫn giữ nguyên `# CONFIG_IGC is not set`, biến dòng lệnh ghi đè đủ để build ra module. Đỡ phải lo sửa nhầm/quên revert `.config` giữa các lần build.

## Bước 2: Vá các file build-tool bị thiếu (arch/arm64)

Gói headers bị cắt các file phụ trợ. Lỗi và cách xử lý theo thứ tự gặp phải:

### 2.1. Thiếu `tools/be_byteshift.h`, `tools/le_byteshift.h`
Lỗi: `scripts/sorttable.c:36:10: fatal error: tools/be_byteshift.h: No such file or directory`

Cách xử lý nhanh: viết tay 2 header nhỏ (hàm xử lý byte-order chuẩn, xem trong lịch sử chat để lấy nội dung), đặt tại:
```
/lib/modules/$(uname -r)/build/tools/include/tools/be_byteshift.h
/lib/modules/$(uname -r)/build/tools/include/tools/le_byteshift.h
```

### 2.2. Thiếu `arch/arm64/tools/{cpucaps,sysreg,gen-cpucaps.awk,gen-sysreg.awk}`
Lỗi: `No rule to make target 'arch/arm64/tools/gen-cpucaps.awk'`

**Đây là file dữ liệu thật (danh sách capability CPU ARM64), không thể viết tay chính xác** → phải lấy từ mã nguồn kernel thật (xem Bước 3), copy đè vào:
```
/usr/src/linux-headers-<ver>/3rdparty/canonical/linux-noble/arch/arm64/tools/
```

⚠️ Nếu build sinh header `cpucap-defs.h` báo thiếu tên capability cụ thể (ví dụ `ARM64_WORKAROUND_SPECULATIVE_SSBS`), so sánh với danh sách tên thực sự dùng trong `arch/arm64/include/asm/cpucaps.h` (file này *có sẵn* trong headers, không bị thiếu) bằng:
```bash
grep -oE 'ARM64_[A-Z0-9_]+' arch/arm64/include/asm/cpucaps.h | sort -u
```
rồi bổ sung tên còn thiếu (bỏ tiền tố `ARM64_`) vào cuối file `cpucaps` datafile.

### 2.3. Bỏ qua bước `vdso_prepare` (không cần cho module ngoài)
Lỗi: `No rule to make target 'arch/arm64/kernel/vdso/vgettimeofday.o'`

**Nguyên nhân**: chạy `make prepare` (target tổng) sẽ kéo theo build `vdso` — chỉ cần khi build `vmlinux` đầy đủ, KHÔNG cần cho module ngoài.

**Cách xử lý**: chạy `make prepare` để nó sinh xong các header cần thiết (cpucap-defs.h, sysreg-defs.h...) rồi **kệ nó báo lỗi vdso ở cuối** — không sao, các header cần đã sinh xong trước khi tới bước đó:
```bash
sudo make prepare   # sẽ lỗi ở vdso_prepare, chấp nhận được
```
Sau đó build module trực tiếp bằng `M=...` (không dùng `make prepare`/`modules_prepare` trần trụi nữa) — vì khi có `M=`, biến `KBUILD_EXTMOD` được set, toàn bộ khối `ifeq ($(KBUILD_EXTMOD),)` chứa `vdso_prepare` trong `arch/arm64/Makefile` sẽ **tự động bị bỏ qua**.

> **Cập nhật:** toàn bộ Bước 2 (2.1, 2.2, 2.3) **không cần lặp lại** khi build cho kernel RT — gói `nvidia-l4t-rt-kernel-headers` đầy đủ hơn hẳn, không bị cắt bớt các file này. Xem mục cuối file.

## Bước 3: Lấy mã nguồn driver `igc` + file arch/arm64/tools thật

Gói headers **hoàn toàn không có source `.c` của driver** (chỉ có `Makefile`/Kbuild rỗng). Lấy trực tiếp từ kernel.org qua git sparse-checkout (nhẹ, không tải cả kernel):

```bash
cd /tmp
git clone --depth 1 --filter=blob:none --sparse https://github.com/torvalds/linux.git -b v6.8
cd linux
git sparse-checkout set drivers/net/ethernet/intel/igc arch/arm64/tools arch/arm64/kernel/vdso
```

Copy driver source vào đúng chỗ:
```bash
sudo cp /tmp/linux/drivers/net/ethernet/intel/igc/*.c \
        /tmp/linux/drivers/net/ethernet/intel/igc/*.h \
        /lib/modules/$(uname -r)/build/drivers/net/ethernet/intel/igc/
```

Copy đè các file arch/arm64/tools thật (thay bản viết tay/thiếu ở Bước 2.2):
```bash
TOOLS_DIR=/usr/src/linux-headers-<ver>/3rdparty/canonical/linux-noble/arch/arm64/tools
sudo cp /tmp/linux/arch/arm64/tools/{cpucaps,sysreg,gen-cpucaps.awk,gen-sysreg.awk} $TOOLS_DIR/
```

Sau đó **xoá header cũ và chạy lại `make prepare`** để sinh lại từ dữ liệu thật:
```bash
sudo rm -f /lib/modules/$(uname -r)/build/arch/arm64/include/generated/asm/cpucap-defs.h
sudo rm -f /lib/modules/$(uname -r)/build/arch/arm64/include/generated/asm/sysreg-defs.h
cd /lib/modules/$(uname -r)/build
sudo make prepare   # vẫn lỗi vdso ở cuối, chấp nhận được
```

Nếu thiếu vài entry lẻ (như `ARM64_WORKAROUND_NVIDIA_CARMEL_CNP` — đặc thù patch NVIDIA, hoặc `WORKAROUND_SPECULATIVE_SSBS` — bản vá bảo mật mới hơn v6.8.0), bổ sung thủ công vào file `cpucaps` như hướng dẫn ở 2.2.

> **Cập nhật:** khi build lại cho kernel RT, mã nguồn driver `igc` **không cần tải lại từ kernel.org** — đã có sẵn cục bộ trong `public_sources_39.2` (NVIDIA cung cấp kèm BSP đầy đủ). Xem mục cuối file.

## Bước 4: Build module

GCC mới hơn kernel cũ có thể sinh cảnh báo `-Werror=return-type` (false positive trong `atomic.h`/`cmpxchg.h`, do inline asm). Tắt riêng cảnh báo này qua `KCFLAGS`:

```bash
cd /lib/modules/$(uname -r)/build/drivers/net/ethernet/intel/igc
sudo make -C /lib/modules/$(uname -r)/build M=$(pwd) KCFLAGS="-Wno-error=return-type" modules
```

Build thành công sẽ ra file `igc.ko` trong thư mục này.

## Bước 5: Load & cài persistent

```bash
# Load thử
sudo insmod /lib/modules/$(uname -r)/build/drivers/net/ethernet/intel/igc/igc.ko
lsmod | grep igc
sudo dmesg | tail -30   # kỳ vọng thấy "Intel(R) 2.5G Ethernet Linux Driver" + MAC card

# Cài vào đúng chỗ hệ thống quản lý (persistent qua depmod)
sudo mkdir -p /lib/modules/$(uname -r)/kernel/drivers/net/ethernet/intel/igc
sudo cp /lib/modules/$(uname -r)/build/drivers/net/ethernet/intel/igc/igc.ko \
        /lib/modules/$(uname -r)/kernel/drivers/net/ethernet/intel/igc/
sudo depmod -a

# Tự động load mỗi khi khởi động
echo "igc" | sudo tee /etc/modules-load.d/igc.conf

sudo reboot
```

Sau reboot, xác nhận module tự load (không cần `insmod` thủ công):
```bash
lsmod | grep igc
ip link show          # sẽ thấy interface dạng enP<domain>p1s0, vd enP1p1s0
```

## Kiểm tra hoạt động

```bash
sudo ip link set enP1p1s0 up
ethtool enP1p1s0 | grep -E "Speed|Link detected"
```

Gán IP test nhanh (không persistent — mất sau reboot, chỉ để test):
```bash
sudo ip addr add 192.168.10.1/24 dev enP1p1s0
```
Từ máy khác cùng dải mạng: `ping 192.168.10.1`, hoặc đo throughput bằng `iperf3`.

## Lưu ý về EtherCAT

- Giao thức **EtherCAT chuẩn chạy ở 100Mbps (100BASE-TX)** — bất kể NIC hỗ trợ tốc độ cao hơn, driver EtherCAT master (SOEM, IgH Master, TwinCAT...) sẽ auto-negotiate xuống 100Mbps khi nối với slave EtherCAT thông thường. Đây là hành vi **đúng chuẩn**, không phải lỗi.
- Nếu test thấy tốc độ chỉ đạt 100Mbps dù nối với thiết bị hỗ trợ cao hơn, và máy đối tác có cài **TwinCAT**: TwinCAT sẽ **chủ động ép** adapter được cấu hình làm Realtime Ethernet xuống 100Mbps cho mục đích EtherCAT, bất kể phần cứng thật sự hỗ trợ gì — kiểm tra bằng cách gỡ tạm cấu hình TwinCAT khỏi adapter đó (qua `TcRteInstall.exe` hoặc icon TwinCAT ở system tray, mục "Show Realtime Ethernet Compatible Devices") để xác nhận.
- Có thể tự kiểm chứng NIC không bị giới hạn tốc độ bằng cách nối 2 cổng mạng trên **cùng một máy Jetson** (I226 ↔ cổng onboard) và xem `ethtool` báo tốc độ negotiate thật (không cần thiết bị ngoài, không phụ thuộc phần mềm bên thứ 3).

## Rủi ro khi build lại lần sau

- Nếu **JetPack/kernel version thay đổi** (update qua `apt`), toàn bộ quy trình này **phải làm lại từ đầu với đúng version kernel mới** (kernel headers khác, có thể danh sách file thiếu cũng khác) — driver `igc.ko` build cho kernel version cũ **sẽ không load được** trên kernel mới hơn.
- Nên backup file `igc.ko` đã build thành công kèm ghi chú chính xác `uname -r` lúc build, để đối chiếu nhanh lần sau xem có cần build lại hay dùng lại được luôn.
- **Từ khi có kernel RT song song với kernel thường, đây không còn là "version thay đổi" đơn lẻ mà là quản lý ≥2 bản build cùng lúc** — xem quy ước đặt tên ở mục dưới.

## ETF / LaunchTime trên i226 (GĐ8 bước 8.5 — đã làm, 29/9/2026)

Mục tiêu: frame cyclic (nhóm motion) rời NIC **đúng thời điểm của chu kỳ**, không phụ thuộc jitter thức dậy của thread RT. Cơ chế: `SO_TXTIME` + qdisc `etf` có **offload** → igc nạp launch time vào descriptor, i226 tự giữ frame đến thời điểm đó. Chi tiết đo: `claude/giai_doan_8_nhat_ky_8_5.md`.

### Nền đồng hồ (bắt buộc trước mọi phép đo)
- ETF so `txtime` với **CLOCK_TAI**; NIC so với **PHC** (`/dev/ptp0`). Hai đồng hồ phải khoá nhau.
- Kernel Jetson có TAI offset = 0 (không ai đặt), nên dùng `-O 0`:
  ```bash
  sudo systemctl stop systemd-timesyncd          # không cho TAI nhảy trong lúc chạy
  sudo phc2sys -s CLOCK_REALTIME -c enP1p1s0 -O 0 -m --step_threshold=1
  sudo tools/etf/clock_check -s 20 | tail -2     # T-01 |PHC-TAI| p99 < 1 µs, T-02 không nhảy > 100 µs
  ```
- Đo được: |PHC−TAI| p99 143–175 ns (sàn đo ~0,5 µs), TAI−MONO trôi ≤ 16 ns / 600 s.

### Cấu hình qdisc (đã chốt)
```bash
# priority 3 -> TC0 (queue 0, ETF); mọi frame khác (priority 0) -> TC2 (queue 2-3, không ETF)
sudo tc qdisc del dev enP1p1s0 root 2>/dev/null
sudo tc qdisc replace dev enP1p1s0 parent root handle 100 mqprio num_tc 3 \
     map 2 2 1 0 2 2 2 2 2 2 2 2 2 2 2 2 queues 1@0 1@1 2@2 hw 0
sudo tc qdisc add dev enP1p1s0 parent 100:1 etf clockid CLOCK_TAI delta 400000 offload
tc qdisc show dev enP1p1s0 | grep "etf.*offload on"    # phải thấy, trước VÀ sau mỗi lần đo
sleep 90                                                # igc reset khi đổi qdisc: chờ phc2sys khoá lại
```
Gỡ sau buổi đo: `sudo tc qdisc del dev enP1p1s0 root`.

### Tham số master (`ecm_run --link etf`)
| Tham số | Giá trị | Lý do |
|---|---|---|
| ETF `delta` | **400 µs**, offload | Quét delta 200/300/400 (600 s mỗi ca): 200 → 2 MISSED, 300 → 1, 400 → 0 |
| `--etf-lead-us` (thức sớm) | **350 µs** | Lead **< delta**: thread gửi tự dequeue frame, không phụ thuộc hrtimer của qdisc (nguồn gốc MISSED). Đuôi wake jitter đo được 144–277 µs (không isolcpus/nohz_full): lead 150 → 1 INVALID / 600 k; lead 200 chỉ vừa đủ |
| `--etf-asap-us` | **150 µs** | Frame hẹn giờ chỉ qua ETF nếu còn ≥ asap tới launch; trễ hơn → gửi ngay (đếm `late`) |
| SO_PRIORITY | 3 | mqprio map → TC0 → ETF |
| Frame khác (config, mailbox, IO, diag) | priority 0, gửi ngay | Không cần launch time; nếu qua ETF với asap sẽ ăn mất ngân sách nhận của nhóm IO (R-02 lượt 1: IO mất 44 % chu kỳ ở N=32) |
| Hạn chót nhận trong tick | `launch + cycle − asap − 150 µs` | Tính từ thời điểm phát, không từ lúc thức (lead chỉ che giấc ngủ) |

Bản vá SOEM: `patches/soem-txtime.patch` (`ecx_txtime_enable`, `ecx_txtime_set_next`, counters `txtime_late/bypass/send_err`). Tắt mặc định → đường af_packet và golden không đổi.

### Kết quả đo
- **Độ chính xác phát** (`txtime_probe`, HW TX timestamp, 600 k frame): `launch_err` = tx_ts − target có offset cố định **~314 ns**, spread p50→max **~30 ns**. So với không ETF (af_packet): p50 +24,8 µs, p99.99 89 µs, max 109 µs. ETF không offload (phần mềm): frame rời ở `txtime − delta` và còn MISSED.
- **R-02 A/B** (`ecm_run` trên i226 ↔ `soft_bus` trên `enP8p1s0`):

| | af_packet N=8 | etf N=8 | af_packet N=32 | etf N=32 |
|---|---|---|---|---|
| WKC noframe (motion / IO) | 4 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| DC \|e\| p99 | 22 µs | **12 µs** | 24 µs | 22 µs |
| ETF missed / invalid | — | 0 / 0 | — | 0 / 0 |

- Hồi quy `--link etf` phần mềm trên veth nhiều hàng đợi: `tools/etf/run_etf_veth.sh` (cũng là job CI `etf-soft`).

### Điều kiện vận hành (checklist trước khi chạy `--link etf`)
1. NetworkManager **không** quản lý i226: `/etc/NetworkManager/conf.d/99-ethercat-unmanaged.conf` → `[keyfile] unmanaged-devices=interface-name:enP1p1s0`. (NM từng reset qdisc giữa buổi đo.) Khi dùng loopback với `enP8p1s0`: `sudo nmcli device set enP8p1s0 managed no`.
2. `phc2sys` chạy liên tục; chờ ~90 s sau mỗi lần đổi qdisc.
3. Không có bước nhảy TAI trong lúc chạy: dừng `systemd-timesyncd` (hoặc chỉ cho slew).
4. `sudo jetson_clocks` (wake p50 7 → 2,9 µs; đuôi không đổi).
5. delta ≥ 400 µs, lead < delta.
6. Đổi qdisc bằng **del rồi add** — `tc qdisc replace … offload` báo "Change operation not supported". Kiểm `offload on` trước và sau.
7. Không SSH/traffic qua i226 hay cổng onboard khi đo (dùng SSH qua USB-C device mode `192.168.55.1`).

### Bẫy đã gặp
- Sau `tc qdisc del` (bỏ offload) i226 có lúc `NO-CARRIER`: `ip link down/up` và `ethtool -r` không đủ → **rút/cắm lại cáp** ở i226.
- `make -B` ecm_run làm mất file capabilities → `ecx_init` fail ngay: `make -C apps/ecm_run setcap`.
- ETF làm **root** qdisc (không mqprio) sẽ drop mọi frame không hẹn giờ, kể cả config → `--link etf` bắt buộc mqprio.
- Probe: socket bind đúng EtherType nhận lại frame của chính nó và đầy rcvbuf → probe dùng protocol 0 (TX-only).
